## Критический блокер: лиды сейчас не доходят

`POST /api/partner-lead` с валидной по форме, но тестовой заявкой возвращает:

```json
{"ok":false,"error":"Не удалось отправить заявку. Попробуйте ещё раз через минуту."}
```

HTTP status: `503`.

Причина подтверждена конфигурацией Worker:

- `GET /workers/scripts/cleaning-rating/secrets` возвращает пустой список;
- в `wrangler.jsonc` нет `NEXT_PUBLIC_TURNSTILE_SITE_KEY`;
- в актуальных bindings нет публичного Turnstile-ключа;
- HTML `/for-partners` и `/for-brands` не содержит Turnstile widget/script.

Следствия:

1. `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` не настроены → `forwardToTelegram()` возвращает false.
2. В production `leadDeliveryRequired()` = true → endpoint честно возвращает 503 до записи лида.
3. `TURNSTILE_SECRET_KEY` не настроен → серверная bot-проверка фактически выключена.
4. `NEXT_PUBLIC_TURNSTILE_SITE_KEY` отсутствует в билде → клиент не рендерит виджет. Важно: `NEXT_PUBLIC_*` обычно вшивается в client bundle на билде, поэтому одного runtime-var может быть недостаточно; нужен redeploy с ключом.
5. `PII_HASH_PEPPER` не настроен → если запись когда-либо пройдёт, SHA-256 телефона останется словарно перебираемым.

Минимальный набор Worker secrets/vars перед запуском продаж:

- `TELEGRAM_BOT_TOKEN` — secret
- `TELEGRAM_CHAT_ID` — secret
- `PII_HASH_PEPPER` — secret
- `TURNSTILE_SECRET_KEY` — secret
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` — public build-time env/var + redeploy

## Критический блокер: прод-админка фактически недоступна владельцу

Публично `/admin` закрыт — это правильно. Но Cloudflare API по Access возвращает:

```text
access.api.error.not_enabled: Access is not enabled
```

То есть Cloudflare Access на аккаунте не включён. Значит, сейчас нет легитимного способа получить заголовок `cf-access-authenticated-user-email` и открыть прод-админку. Тестовая подделка заголовка извне вернула 404, но это не заменяет нормальный доступ владельца.

Нужно либо включить Cloudflare Zero Trust Access и policy для `/admin` + `/api/admin/*`, либо заменить доступ на другой серверный auth flow. До этого «Радар спроса», статусы лидов и управление кампаниями в проде недоступны.

## Рекламный движок

По коду и тестам:

- `solution.sponsored_product` требует active campaign, сроки, бюджет, гео, erid для RU, product safety, verified compatibility exact match по material+surface и relevance.
- Подтверждённая совместимость есть только у `prod-prochem-stainpro` и `prod-prochem-spotter`.
- Seed-кампании имеют статус `draft`, поэтому публичные слоты пусты — это корректная защита от неоплаченной рекламы.
- SSR-рендер рекламы серверный, без клиентской подгрузки креатива; тесты подтверждают, что draft-кампании не выходят в слоты.
- `EmptySlotPitch` сейчас фактически не используется на публичных протоколах (`showPitchWhenEmpty` нигде не включён), поэтому свободные слоты не продают себя прямо с высокоинтентных страниц.

Риск CLS есть не в самом серверном рендере, а в клиентском гео-гейте: `AdImpression` может вернуть `null` после гидратации, если регион пользователя отличается от SSR/default или для RU нет erid. Удаление уже отрисованного блока способно дать layout shift. Практического impact сейчас нет, потому что активных кампаний нет; перед запуском нужно либо делать гео-решение до рендера, либо скрывать без размонтирования с сохранением геометрии.

## Радар спроса

`buildDemandRadar` корректно строит:

- темы по intent keywords и просмотрам протоколов;
- распределение B2C/B2B/PRO;
- тренды категорий за текущие/предыдущие 30 дней;
- missed queries из поиска.

Ограничения:

- фактические данные прод-D1 не проверены из-за отсутствия D1 permission;
- при ошибке D1 функции возвращают пустые массивы, поэтому в админке сбой БД может выглядеть как «нет спроса»;
- пока `/admin` недоступен владельцу, радар не помогает продажам.

## Три шага к первым спонсорским слотам и выручке

1. **Сначала восстановить коммерческий контур:** настроить Telegram/Turnstile/PII secrets, включить Cloudflare Access для владельца, провести end-to-end тест: форма → Telegram → hash в D1 → лид виден в `/admin` → статус меняется.
2. **Запустить первый product pilot без новых разработок:** после подтверждения и применения `seed-stage10.sql` активировать одну кампанию `solution.sponsored_product` для Prochem Stain Pro только на BY и только на протоколах с exact verified material (`vino-na-divane`, `kofe-na-tekstile`). Для RU не включать до erid. CTA должен вести на реального дилера с промокодом.
3. **Продать первые PRO/dealer слоты фиксированными пакетами:** выбрать 1–2 категории по «Радару спроса» и предложить компаниям PRO-полку на 6 месяцев по founder price; параллельно найти 1 авторизованного дилера химии на регион и включить `dealer.local_partner` с промокодом. Включить `EmptySlotPitch` на высокоинтентных протоколах или перенести эти CTA в заметное место `/for-brands`, чтобы свободные слоты приводили входящие заявки.

Без первого шага все формы теряют выручку на входе, даже если рекламный движок исправен.
